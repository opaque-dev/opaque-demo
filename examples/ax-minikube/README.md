# Run an AX task under repository-configured Opaque policy

Inspect [policies/support-status.yaml](policies/support-status.yaml), review a
scope with Opaque's native reviewer, then let the AX child submit the checked-in
proposals to the real broker. The broker owns authorization, approval validation,
provider credential custody, durable attempt consumption, and outcome recording.

```sh
opaque authority-policy validate examples/ax-minikube/policies/support-status.yaml --json
opaque authority-policy compile examples/ax-minikube/policies/support-status.yaml --json
```

This uses **unreleased pinned core source**, not a released CLI contract. The
Google AX task runner executes in minikube; no AX control plane or Agent Substrate
is installed. The local OIDC identity fixture and HTTPS support API are synthetic.
Native human approval is required and is never generated by the fixture.

## The repository defines the demo

| File | Responsibility |
| --- | --- |
| [policies/support-status.yaml](policies/support-status.yaml) | Allowed status, two-resource/two-attempt/ten-minute ceilings, required scope review, autonomous execution within the approved scope |
| [broker/config.toml.in](broker/config.toml.in) | Sealed policy digest and identity binding, enrolled reviewer, native backend, tenant, provider endpoint and private credential paths |
| [workload/scope.json](workload/scope.json) | Exact proposed cases, status, duration and attempt count; this request is not approval |
| [workload/actions.json](workload/actions.json) | An out-of-policy `closed` proposal followed by two `resolved` proposals |
| [workload/task.yaml](workload/task.yaml) | AX command and workspace |
| [k8s/broker.yaml](k8s/broker.yaml), [k8s/runner.yaml](k8s/runner.yaml), [k8s/storage.yaml](k8s/storage.yaml) | Separate broker and AX pods; durable broker ledger, socket and workload records |
| [worker.py](worker.py) | Read AX metadata, bind stable request IDs, call `opaque scope plan/activate/run/outcome`, retain responses without automatic retries |
| [fixtures/](fixtures/) | Local identity/provider protocol services and bootstrap transport; no Opaque policy engine or approval signer |

Changing Python is unnecessary to change the policy. Edit the policy manifest,
compile it, and bind the resulting digest through the ordinary operator
seal/restart procedure. This demo's `deploy` creates a **new** owned namespace and
immutable ConfigMaps; it is not a policy-update operator. Never delete custody or
change generation to apply an update to an existing deployment. Staging YAML does
not activate policy or authorize an action.

The policy is a ceiling. A broader scope request must be rejected by the broker;
a narrower approved scope can further constrain it. Removing `closed` from the
allowed statuses is enforced by the actual Opaque runtime, not a Python check.

## Build the pinned binaries and image

Prerequisites: Docker, minikube, Python 3.12+ with PyYAML 6.0.3, Git, Go compatible
with the AX pin, Rust compatible with the Opaque pin, and a supported native
reviewer host. This preparation uses macOS arm64. Linux container execution does
not supply a native reviewer by itself. Reserve 4 CPUs and 8 GiB for minikube.

From this demo repository:

```sh
python3 -m venv /tmp/opaque-ax-demo-venv
/tmp/opaque-ax-demo-venv/bin/pip install -r examples/ax-minikube/requirements.txt

git clone https://github.com/opaque-dev/opaque.git /tmp/opaque-ax-demo-core
git -C /tmp/opaque-ax-demo-core checkout --detach 180e66fe6c854d962074e8ff4e694a29689af623
git clone https://github.com/google/ax.git /tmp/opaque-ax-demo-ax
git -C /tmp/opaque-ax-demo-ax checkout --detach f009cc81c9a571073bc1dd58cd2ed934bf2d5b1c
(cd /tmp/opaque-ax-demo-core && OPAQUE_BUILD_REVISION=180e66fe6c854d962074e8ff4e694a29689af623 cargo build --locked -p opaque -p opaque-approver -p opaque-approve-helper)

AX_DEMO_BUILD=$(mktemp -d /tmp/opaque-ax-build.XXXXXX)
mkdir "$AX_DEMO_BUILD/source"
git -C /tmp/opaque-ax-demo-core archive 180e66fe6c854d962074e8ff4e694a29689af623 | tar -xf - -C "$AX_DEMO_BUILD/source"
cp examples/ax-minikube/Dockerfile "$AX_DEMO_BUILD/"
cp -R examples/ax-minikube "$AX_DEMO_BUILD/demo"
cp /tmp/opaque-ax-demo-ax/LICENSE "$AX_DEMO_BUILD/ax-LICENSE"
# Use GOARCH=amd64 for an amd64 minikube node.
(cd /tmp/opaque-ax-demo-ax && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -o "$AX_DEMO_BUILD/ax-task-runner" ./cmd/ax-task-runner)
docker build --build-arg OPAQUE_BUILD_REVISION=180e66fe6c854d962074e8ff4e694a29689af623 \
  --build-arg AX_REVISION=f009cc81c9a571073bc1dd58cd2ed934bf2d5b1c \
  -t opaque-ax-demo:policy "$AX_DEMO_BUILD"
minikube start -p opaque-ax-demo --driver=docker --cpus=4 --memory=8192 \
  --disk-size=30g --kubernetes-version=v1.35.1 --keep-context
```

The pinned public Opaque revision remains BUSL-1.1. The proposed Apache-2.0 change
is separate and does not relabel this image. AX uses Apache-2.0. Both licenses are
included in the image. No image is pushed to a registry.

## Prepare, review, run, inspect

```sh
/tmp/opaque-ax-demo-venv/bin/python -B scripts/ax_minikube_demo.py \
  --state /tmp/opaque-ax-policy-session deploy --image opaque-ax-demo:policy \
  --native-bin /tmp/opaque-ax-demo-core/target/debug
/tmp/opaque-ax-demo-venv/bin/python -B scripts/ax_minikube_demo.py \
  --state /tmp/opaque-ax-policy-session serve
```

Open <http://127.0.0.1:19740/>. `deploy` compiles with the actual image's Opaque
binary, enrolls a fresh host reviewer key, seals the broker configuration, starts
the broker and AX runner, and checks that an undelegated AX process is refused.
It does not open native review or send provider writes. Bootstrap configuration
omits the policy until the reviewer identity and workstation are enrolled; the
final broker startup mounts the immutable policy and pins its compiler digest.

When the reviewer is present, run this explicit operator command in another terminal:

```sh
/tmp/opaque-ax-demo-venv/bin/python -B scripts/ax_minikube_demo.py \
  --state /tmp/opaque-ax-policy-session review
```

Three native reviews occur:

1. Delegate an operator session for read-only `scope_snapshot`. Its reported policy
   digest and identity must equal the compiled repository policy. The administrative
   session stays in the trusted broker-side protocol client, outside the AX pod.
2. Delegate the requester to the AX workload. The AX child calls the actual
   `opaque scope plan --manifest /etc/demo/workload/scope.json` command.
3. Review that scope with the native reviewer. The AX child calls `opaque scope
   activate`; only a valid broker-verified receipt permits activation.

The browser shows the policy as **verified** only after the authenticated snapshot
matches. Choose **Run approved AX workload** after activation. Each proposal goes
through `opaque scope run`; there is no demo authorization implementation. Inspect
the exact response and the subsequent read-only `scope outcome` result.

The `closed` proposal should be refused. The fixture accepts one `resolved`
write normally; for `lost-ack` it records the effect then closes the connection.
The broker must preserve the uncertain outcome and charge the attempt. These are
expected behaviors until an actual approved run is observed; the UI invents no
successful results. The worker journals intent before dispatch and never retries
a write. A restart after planning puts the run on hold, retaining prior records.

```sh
/tmp/opaque-ax-demo-venv/bin/python -B scripts/ax_minikube_demo.py \
  --state /tmp/opaque-ax-policy-session inspect
```

The runtime directory must be outside Git. If preparation or review fails, retain
that directory and namespace for inspection. There is no automatic restart,
re-enrollment, repeated review, reset, or retry command. The review command refuses
to repeat a previously attempted delegation. Expired or interrupted sessions need
an explicit operator recovery procedure before further work.

## Boundaries and verification

Provider credentials and the ledger are mounted only in trusted broker-side
containers. The AX pod gets the broker socket, a requester session in memory-backed
temporary storage, the public task configuration and its own evidence volume.
Reviewer signing keys remain on the host. The cluster operator remains trusted;
minikube's default networking is not claimed to enforce egress restrictions.
Synthetic OIDC identities do not establish real organizational identity.

The loopback HTTP view serves only selected assets and sanitized observation
fields. It checks Host and Origin before the run request. Native authentication
is available only through the explicit terminal review command. Ctrl-C stops the
view; `minikube stop -p opaque-ax-demo` stops this dedicated cluster while retaining
storage. Deleting namespace/PVCs destroys retained history and is a separate action.

```sh
/tmp/opaque-ax-demo-venv/bin/python -B -m unittest discover -s scripts -p test_ax_minikube_demo.py -v
node --check examples/ax-minikube/demo.js
```

The earlier synthetic Rust crash producer is retained separately in
[ax-recovery-fixture](../ax-recovery-fixture). It is not the policy-governed AX
workflow and cannot serve as evidence of native human approval or live broker RPC.
